# mist install guide

Two paths: plain `kubectl` manifests (this directory) or the
self-contained Helm chart (`helm/mist/`, no external dependencies).
Both install the same stack; the chart additionally templates images,
resource limits, and Postgres persistence.

## Prerequisites

- A Linux-node cluster (kind works; the eBPF sensor needs BTF on ≥5.15).
  Stock kind qualifies: `kind create cluster --name mist`.
- `kubectl` pointed at it. `helm` for the chart path.

## Path A — kubectl manifests

Apply **in this order** (later steps depend on earlier ones):

```sh
# 1. Namespace + RBAC for agent and operator.
kubectl apply -f deploy/agent-rbac.yaml -f deploy/operator-rbac.yaml

# 2. CRDs (generated by the operator itself; checked in for review).
kubectl apply -f deploy/crds/

# 3. Postgres for flow/alert history (10Gi PVC, default StorageClass).
kubectl apply -f deploy/postgres.yaml

# 4. API + operator. The :dev tags are never pulled (IfNotPresent), so
#    build and kind-load them first (host-built eBPF object + trunk
#    bundle are COPYd into the images):
(cd crates/mist-ebpf && cargo +nightly build -Z build-std=core --release)
cp crates/mist-ebpf/target/bpfel-unknown-none/release/mist-ebpf mist-ebpf.o
(cd crates/mist-dashboard && trunk build --release)
docker build -t mist-api:dev -f docker/api.Dockerfile .
docker build -t mist-operator:dev -f docker/operator.Dockerfile .
docker build -t mist-agent:dev -f docker/agent.Dockerfile --build-arg EBPF_OBJECT=mist-ebpf.o .
kind load docker-image mist-api:dev mist-operator:dev mist-agent:dev --name mist
kubectl apply -f deploy/api-deployment.yaml -f deploy/operator-deployment.yaml

# 5. Default monitor (the operator renders the agent DaemonSet from this).
kubectl apply -f deploy/samples/

# 6. Verify.
kubectl wait --for=condition=Established crd/trafficmonitors.mist.io --timeout=60s
kubectl wait --for=condition=Established crd/anomalyalerts.mist.io --timeout=60s
kubectl -n mist rollout status deployment/mist-operator --timeout=180s
kubectl -n mist rollout status deployment/mist-api --timeout=180s
kubectl -n mist get trafficmonitor default
kubectl -n mist get daemonset mist-agent   # rendered by the operator, not applied
```

The agent DaemonSet is owned by the operator (see
`crates/mist-operator/testdata/agent-daemonset.yaml` for the golden shape) —
do not apply a static copy; the operator creates and updates it. The oldest
`TrafficMonitor` wins; extras are marked `Superseded`; deleting all of them
removes the DaemonSet.

## Path B — Helm chart

```sh
helm install mist helm/mist --namespace mist --create-namespace
kubectl apply -f deploy/samples/   # default TrafficMonitor (namespace: mist)
```

Useful overrides:

```sh
# Real images + external database instead of bundled Postgres.
helm install mist helm/mist --namespace mist --create-namespace \
  --set api.image=registry.example.com/mist-api:0.1.0 \
  --set operator.image=registry.example.com/mist-operator:0.1.0 \
  --set agent.enabled=false \
  --set postgres.enabled=false \
  --set api.databaseUrl=postgres://mist:secret@db.internal:5432/mist

# Persistent bundled Postgres.
helm install mist helm/mist --namespace mist --create-namespace \
  --set postgres.persistence.enabled=true
```

`agent.enabled` stays `false` (the default) whenever the operator runs —
the operator renders that DaemonSet itself, and a static copy would fight
it. Set it `true` only for operator-less setups.

## Port-forwards

```sh
kubectl -n mist port-forward svc/mist-api 3000:3000 &       # REST + WS + dashboard
kubectl -n mist port-forward svc/mist-postgres 5432:5432 &  # direct DB access
curl localhost:3000/healthz                                 # -> ok
curl localhost:3000/metrics | head -20                      # public Prometheus scrape
# Dashboard: http://localhost:3000/login (seed an admin first — see below).
# REST needs a JWT (login first); the WS token travels in ?token=:
TOKEN=$(curl -s -X POST localhost:3000/api/auth/login \
  -H 'content-type: application/json' \
  -d '{"email":"admin@example.com","password":"..."}' | \
  python3 -c 'import json,sys; print(json.load(sys.stdin)["token"])')
curl -H "authorization: Bearer $TOKEN" localhost:3000/api/flows | head -c 300; echo
curl -H "authorization: Bearer $TOKEN" localhost:3000/api/alerts | head -c 300; echo
# WebSocket: any WS client against "ws://localhost:3000/api/ws?token=$TOKEN"
```

## Local-dev binaries (no images needed)

Until container images are published, run the control plane from source
against the in-cluster Postgres:

```sh
kubectl -n mist port-forward svc/mist-postgres 5432:5432 &
DATABASE_URL=postgres://mist:mist-dev-password@localhost:5432/mist \
OPERATOR_WEBHOOK_URL=http://localhost:8081/alerts \
ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD=dev-only \
JWT_SECRET=dev-only \
  cargo run -p mist-api   # JWT_SECRET is required (any value for local dev)
cargo run -p mist-operator   # needs kube context; watches OPERATOR_NAMESPACE (default mist)
```

## Seeding auth

Login is live (`docs/auth.md`), but the manifests intentionally ship no
credentials — the API pod blocks until the `mist-api-auth` Secret exists
and refuses to start without `JWT_SECRET`. Copy the template (gitignored),
fill it in, and apply it right after the workloads:

```sh
cp deploy/api-auth-secret.example deploy/api-auth-secret.yaml
$EDITOR deploy/api-auth-secret.yaml   # jwt-secret, admin-*, ingest-token
kubectl apply -f deploy/api-auth-secret.yaml
```

Or create it imperatively for a dev cluster:

```sh
kubectl -n mist create secret generic mist-api-auth \
  --from-literal=jwt-secret="$(openssl rand -hex 32)" \
  --from-literal=admin-email=admin@example.com \
  --from-literal=admin-password='s3cret-for-kind' \
  --from-literal=ingest-token='kind-ingest-token'
```

Missing/empty admin keys fail login closed (401 for everyone); a missing
`ingest-token` key leaves `/api/ingest` open (dev only — the agents from
the default sample then also send no token). Also replace the dev Postgres
password (`mist-dev-password` in `deploy/postgres.yaml`, overridable via
`postgres.auth.password` in the chart).

## Probes

- `mist-api`: HTTP `GET /healthz` liveness + readiness on port 3000.
- `mist-operator`: TCP socket probes on 8081 — the operator exposes only
  the `POST /alerts` webhook, no HTTP health endpoint.

## Teardown

```sh
kubectl delete -f deploy/samples/
kubectl delete -f deploy/api-deployment.yaml -f deploy/operator-deployment.yaml
kubectl delete -f deploy/postgres.yaml
kubectl delete -f deploy/crds/
kubectl delete -f deploy/agent-rbac.yaml -f deploy/operator-rbac.yaml
# Helm path: helm uninstall mist --namespace mist
```

Regenerate the CRDs after changing `crates/mist-operator/src/crd.rs`:

```sh
cargo run -p mist-operator -- --print-crds > /tmp/crds.yaml
# split into deploy/crds/trafficmonitors-crd.yaml + anomalyalerts-crd.yaml,
# then copy both to helm/mist/crds/ (keep all three in sync)
```
